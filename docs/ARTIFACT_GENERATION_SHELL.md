# Stage 10I — Binary shell artifact destinations

**Status:** Termux RUN_COMMAND stdin-chunk and Shizuku ParcelFileDescriptor pipe implementations are present in PR #58. TERMUX_RISH remains intentionally unavailable for binary artifact output until end-to-end stdin forwarding and cancellation are independently proven.

**Validation:** Focused pure policy tests were added but not executed. No Gradle tests, builds, instrumentation tests, or device checks were run. Final protocol verification belongs to Stage 10J.

## Shared behavior

- The single artifact_create tool selects destination_type=shell, an explicit backend, and an absolute path whose final component exactly matches file_name.
- The ordinary artifact approval action shows the exact format, filename, backend identity, destination path, estimated size, and overwrite intent. The shell destination adapter does not silently request a different backend's approval or switch identities.
- SAF access is independent. A persisted Gallery document-tree grant does not authorize a shell backend to read or write the same path.
- The generator writes into a quota-bounded app-private staging file rather than holding the complete artifact in memory.
- The engine's generated byte count and SHA-256 are passed to the selected destination. The destination verifies both before finalization.
- Shell destinations require an existing parent folder. Gallery does not create arbitrary directory trees for shell output.
- Partial output is removed on failure or cancellation where the selected backend remains reachable. A backend loss can still make cleanup unconfirmable; that must be reported as failure, never success.

## TERMUX — RUN_COMMAND stdin chunks

- Uses the official com.termux.RUN_COMMAND_STDIN extra; no binary data is placed in command text or shell arguments.
- Raw chunks are capped at 180 KiB. Base64 encoding remains below the 256 KiB configured stdin-string bound, with headroom below the documented approximate 500 KB combined Intent-extra ceiling.
- Each chunk is a separate foreground RUN_COMMAND request so the stdin payload is delivered to the command. The command is a fixed base64 -d redirection to a random same-directory .part path.
- The adapter preflights the parent folder, target type, and required base64/sha256sum commands; it never creates a destination directory.
- After all chunks, Termux reports the staged file's byte count and SHA-256. Only matching values permit same-directory mv finalization. No-overwrite mode uses no-clobber rename semantics and checks that the temporary file was consumed.
- Failure/cancellation attempts rm -f on the temporary path through the same Termux identity.
- The target path must be writable by the Termux app UID. A Gallery SAF grant does not confer this access.

## SHIZUKU — ParcelFileDescriptor pipe

- Adds a dedicated writeBinaryFile AIDL method. The Binder transaction carries a ParcelFileDescriptor and bounded metadata, never an artifact-sized byte array.
- The app creates a one-shot pipe, streams the staged file into its write end, and invokes the Shizuku UserService with the read end.
- The UserService runs under the Shizuku shell identity (uid 2000, not root), validates the absolute path, existing parent, target type, overwrite flag, byte ceiling, timeout, and expected SHA-256.
- The service copies in 32 KiB chunks into a randomly named temporary file in the destination folder, flushes and syncs it, verifies the byte count/hash, then renames it into place.
- The service deletes its temporary file on incomplete transfer or verification failure. Closing the pipe on cancellation signals EOF so incomplete transfers fail verification and clean up.
- The target path must be writable by the Shizuku shell identity. A Gallery SAF grant does not confer this access.

## TERMUX_RISH — deliberately unavailable

The existing Rish route wraps a command with rish -c and launches it through Termux RUN_COMMAND. It is not assumed that Termux's stdin extra reaches the remote Shizuku shell process. Until a real end-to-end transfer proves stdin forwarding, bounded cancellation, cleanup, and final hash verification, the adapter rejects TERMUX_RISH binary output. It never substitutes TERMUX or SHIZUKU.
